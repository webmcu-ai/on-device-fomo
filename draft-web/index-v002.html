index-v002 — FOMO object detection trainer for the XIAO ESP32-S3 ML Kit

Pairs with firmware-v002.ino. Label boxes, train the same 2-conv + 1x1 FOMO head in plain JS, check detections, clean the data, write myWeights.bin back to the SD card. Single file, no network.

1 · Data source

Nothing loaded yet. Pick the SD card root (it contains images/ and header/) or load a zip of it. Desktop Chrome or Edge can read and write the card directly.

2 · Classes and data

Class 0 is the background class (the firmware gives it no boxes: all-zero target). Classes 1.. are objects. Boxes are fractions of the model frame: the stored JPEG after the firmware's horizontal software flip, which is what every image on this page shows. An object image without a box is trained on the firmware's default centred box (35%–65%).

3 · Train


Model layout (compile-time in the firmware)











Changing the layout discards the model in memory and redraws every model input view; it never touches files on the card. The kernel stays 3x3 because the firmware loops hard-code it.


Training settings
















STOP keeps the current model in memory and does not save. Risks: near-duplicate burst images inflate validation numbers; web file names (web_…) sort after device names (img_…), so "last N by name" can hold out web images only. A class with N or fewer images is held out completely (firmware rule).


No model yet.




"accuracy" is the firmware's own printed metric: argmax of each class's average map over all classes. Because the firmware trains class 0 toward zero everywhere, background images often count as wrong even when detection is fine. Use the detection table in Analyze instead.
